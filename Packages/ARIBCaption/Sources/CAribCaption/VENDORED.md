# Vendored libaribcaption

Upstream: https://github.com/xqq/libaribcaption
Commit:   da5ae9b1479168c9560161a916e12e6159f116b4
Version:  1.1.2 (from CMakeLists.txt)
License:  ISC-style (see ../LICENSE, copied verbatim)

Only the library sources needed for decoding ARIB STD-B24 captions and
rendering them with CoreText on Apple platforms are vendored. Upstream
`test/`, `screenshots/`, `cmake/`, CI files and the non-Apple renderer
backends (FreeType, Fontconfig, DirectWrite, GDI, Android) are not copied.

## Layout

- `Sources/CAribCaption/include/aribcaption/` – upstream C API headers
  (`include/aribcaption/*.h`). This directory is `publicHeadersPath`, so
  importing the module from Swift never parses C++ headers.
- `Sources/CAribCaption/src/include/aribcaption/` – upstream C++ headers
  (`include/aribcaption/*.hpp`), kept private.
- `Sources/CAribCaption/src/include/base/` – upstream `src/base/*.hpp` and
  `src/base/md5.h` (internal headers shared with the renderer target).
- `Sources/CAribCaption/include/aribcc_config.h` – hand-written static
  replacement for the CMake-generated `aribcc_config.h`.
- `Sources/CAribCaption/src/{base,common,decoder}/` – decoder + C API.
- `Sources/CAribCaptionRenderer/src/{include,src}/renderer/` – renderer, C API
  and CoreText backend, built only on Apple platforms. Its manifest path is
  switched to a stub target on non-Apple hosts.

## Local changes (all outside upstream source files)

1. **No source files were edited.** The split into two SwiftPM targets is purely
   by source file selection, following the `ARIBCC_NO_RENDERER` split that
   upstream CMakeLists.txt already performs. Upstream never references the
   renderer from `src/base`, `src/common` or `src/decoder`, so no
   `ARIBCC_NO_RENDERER` guards had to be added.
2. `include/aribcc_config.h` is written by hand instead of being generated by
   CMake. It defines `ARIBCC_USE_CORETEXT` on `__APPLE__` and
   `ARIBCC_NO_RENDERER` elsewhere.
3. Internal C++ headers moved from `src/base/` to
   `Sources/CAribCaption/src/include/base/`, and the public C++ headers from
   `include/aribcaption/*.hpp` to
   `Sources/CAribCaption/src/include/aribcaption/`, so that only the C API is
   exposed as the Swift module. The renderer target reaches the shared headers
   with a header search path; contents are unchanged.
4. Renderer headers moved from `src/renderer/` to
   `Sources/CAribCaptionRenderer/src/include/renderer/`, contents unchanged.
   They stay out of `publicHeadersPath` so SwiftPM never generates a Clang
   module that parses the Windows / FreeType / SSE headers.

The SwiftPM build defines `ARIBCC_IMPLEMENTATION` and uses C++17, matching
`target_compile_features(... cxx_std_17)` and
`target_compile_definitions(... ARIBCC_IMPLEMENTATION)` in CMakeLists.txt.
It does not pass `-fno-exceptions`, `-fno-rtti`, `-msse`/`-msse2` or
`-fno-aligned-allocation`; those are optional CMake switches (all default to
off except the SSE flags, which are baseline on the supported x86_64 targets) or
optimisations that SwiftPM cannot express without `unsafeFlags`.
